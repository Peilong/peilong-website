# Peilong Li's personal website

Hugo site on the Academic theme (4.6.3), published to https://peilong.github.io. This file holds the working
rules for Claude Code sessions, local and cloud. Keep it free of anything private: this repo is public.

## Build

- Hugo **0.66.0, non-extended**. It works because the compiled SCSS in `resources/_gen` is committed, so keep
  that folder. Use exactly this version; the site is only built and tested with it.
- `themes/academic` is the theme at a pinned commit. **Never edit it.** Put overrides in the site's own
  `layouts/` and `static/` (the footer, icons and partials already live there).
- In a layout that uses baseof, the file must **start** with `{{ define "main" }}` (no comment before it).
- `hugo server -D` previews drafts. Restart it after regenerating many content folders (Hugo 0.66 panics).

## Content

- Blog posts: `content/post/<slug>/index.md`, YAML front matter, `authors: ["admin"]`. New posts start as
  `draft: true`; the owner reviews every post before it goes live. A future `date` makes a post go live that day.
- Posts are written for faculty in every discipline: plain language, no code, concrete steps with tools
  faculty already have. Big topics become a series. Check every factual claim against its primary source.
- Homepage sections: `content/home/`. Courses page: `data/teaching.json` plus the archive generated by
  `scripts/course-archive/` (see its README).
- The CV repo (github.com/Peilong/CV: `cv.tex`, `allmine.bib`) is the source of truth for bio, publications and
  dates. `static/files/cv.pdf` is its compiled PDF. New items go to the CV first.
- Title: Program Director of Computer Science. There is no separate Data Science program anymore.

## Rules

- **Never publish the email address in its raw form**, and no `mailto:` links. Write it as
  `lip AT etown DOT edu`. The publish workflow refuses to deploy a build that contains the raw address.
- Never name a tag or category "Privacy" or "Terms" (the theme footer then links the taxonomy page site-wide).
- Analytics: GA4 is set in `config/_default/params.toml` `[marketing]`. Do not also add it through Tag
  Manager (double counting).
- Design: keep Etown blue and rounded shapes; avoid generic default fonts and icon tiles.

## Games

- **Bit Flip** (`/games/bitflip/`, menu "Games"): `content/games/bitflip/index.md` + `layouts/games/bitflip.html`;
  code in `assets/games/bitflip/`. `core.js` holds the rules and scoring as pure functions and is shared with the
  leaderboard server, so change scoring there only, and keep `node`-testable behavior identical on both sides.
- **Leaderboard**: Cloudflare Worker + D1 in `workers/bitflip/` (API URL in `params.toml` `[games] bitflip_api`;
  empty = no leaderboard). The server deals each game's seed, re-scores submitted solve times with `core.js`, and
  enforces the name rules (`src/names.js`: 2–16 letters/numbers, profanity filter incl. leetspeak and spaced-out
  letters). Admin page: `<bitflip_api>/admin` (hide entries, block names); its key is kept privately by the owner.
- Worker changes: `cd workers/bitflip && npm test && npx wrangler deploy` (needs the owner's Cloudflare login, so
  deploy from the owner's Mac, not from a cloud session). Schema: `schema.sql`.

## Publishing

- `.github/workflows/scheduled-publish.yml` builds the site daily at 12:15 UTC and pushes to
  Peilong/Peilong.github.io when the output changed. It can also be started by hand (Actions → Scheduled
  publish → Run workflow).
- **Cloud sessions** (Claude Code on the web): `scripts/cloud-setup.sh` installs Hugo 0.66.0 and the theme at
  session start. Work on a branch and open a pull request; the owner merges it, and the next workflow run
  publishes. Do not populate or commit `public/` there. To check a build, run `hugo -d /tmp/site-check`, then
  `grep -rIl -i "lip@etown" /tmp/site-check` must print nothing.
- **Local sessions**: `public/` is a submodule of Peilong.github.io. Run `git -C public pull` first (the
  workflow also commits there), build with `hugo`, then commit and push inside `public/`, and push this repo.
  Local copies show a 644→755 mode change on nearly every file, so use `git -c core.fileMode=false add ...`.
